# XHImg

**一次整理，随处调用。**

XHImg 是面向个人自托管的图片管理与随机图 API 服务，采用单管理员模式。将图片保存到本地或 S3 兼容存储，通过文件夹、权限和标签整理资源，用于公开图库、图片直链和随机图接口。

[快速开始](#快速开始) · [配置说明](#配置说明) · [使用指南](#使用指南) · [文档中心](docs/README.md) · [常见问题](#常见问题) · [GPL-3.0](LICENSE)

适合个人图库、博客图片资源管理和随机背景图服务。支持本地与 S3 存储，部署采用单实例；不提供公开注册、匿名上传或多租户功能。

## 功能概览

| 功能       | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| 图片管理   | 多级文件夹、名称与标签搜索、批量操作、回收站、异步缩略图   |
| 权限控制   | 图片默认私有，继承文件夹权限；API Key 按操作与资源范围授权 |
| 公开图库   | 展示公开图片、文件夹和已启用的公开随机图服务               |
| 随机图 API | 全站、文件夹、自定义服务，支持随机图片和 MP4               |
| 断点续传   | 4 MiB 分片、两个文件并发、整文件与分片 SHA-256 校验        |
| 图片处理   | 压缩、格式转换、尺寸限制、可选保留原图与重新处理           |
| AI 归档    | 视觉模型自动分类，支持已有图片批量整理与人工归档           |
| 存储管理   | 本地与 S3 兼容存储，支持迁移预览、校验、暂停和重试         |

图片处理和 AI 归档默认关闭，启用后不会自动修改已有图片。存储迁移需由管理员预览并确认执行。

## 快速开始

以下命令均在项目根目录执行。可选择 Docker Compose 或本地 Node.js 部署，两种方式都需要先准备环境配置。

### 1. 准备配置

复制配置模板：

```sh
cp .env.example .env
```

Windows PowerShell 使用：

```powershell
Copy-Item .env.example .env
```

生成独立的主密钥，不要直接使用模板中的示例值：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

将输出的 **64 位十六进制字符串**写入 `.env` 的 `MASTER_KEY`，将 `PUBLIC_URL` 设置为站点访问来源。本地体验可使用 `http://localhost:9521`；公网部署应使用实际 HTTPS 来源，例如 `https://img.example.com`，同时设置 `COOKIE_SECURE=true`。

`MASTER_KEY` 用于保护存储和 AI 凭证，应固定保存并随数据备份，不要在重启或升级时重新生成，也不要提交到 Git。仅使用 Docker、宿主机未安装 Node.js 时，也可用密码工具生成 32 字节随机值的十六进制表示。

### 2. 启动服务

#### Docker Compose

需要 Docker 和 Docker Compose：

```sh
docker compose up -d --build
docker compose logs xhimg
```

默认访问地址为 `http://localhost:9521`。Compose 使用命名卷 `xhimg-data` 持久化数据，镜像以非 root 用户运行。

镜像内置 FFmpeg 和 FFprobe。使用本地 Node.js 部署时，上传 MP4 需要把两者加入 `PATH`。

#### 本地 Node.js

需要 **Node.js 24** 和 **pnpm 12.8.1**：

```sh
npm install -g pnpm@12.8.1
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Windows 上 `better-sqlite3` 优先使用匹配 Node ABI 的预编译模块；没有对应模块时，需要本地编译工具。

### 3. 创建管理员

打开 `http://localhost:9521/setup`，使用启动日志中的一次性安装令牌创建管理员，密码至少 12 个字符。自定义域名部署时，访问对应域名的 `/setup`。

没有默认账号或密码。安装完成前重启服务会生成新令牌，旧令牌随即失效；安装令牌应保密。

## 配置说明

本地运行从根目录 `.env` 读取配置。Docker Compose 按 [docker-compose.yml](docker-compose.yml) 映射环境变量。

| 变量            | 默认值 / 要求             | 用途                                             |
| --------------- | ------------------------- | ------------------------------------------------ |
| `MASTER_KEY`    | 必填，64 位十六进制字符串 | 自行生成并长期保留的主密钥                       |
| `PUBLIC_URL`    | `http://localhost:9521`   | 对外访问来源，包含协议、域名及必要端口           |
| `HOST`          | `0.0.0.0`                 | 本地运行时的监听地址                             |
| `PORT`          | `9521`                    | 本地运行时的监听端口                             |
| `DATA_DIR`      | `./data`                  | 本地数据目录，相对项目根目录解析，也支持绝对路径 |
| `COOKIE_SECURE` | `false`                   | HTTPS 部署设为 `true`                            |
| `TRUST_PROXY`   | `false`                   | 是否信任反向代理提供的来源信息                   |

Compose 固定容器监听端口为 `9521`、数据目录为 `/app/data`；修改 `.env` 的 `HOST`、`PORT` 或 `DATA_DIR` 不会更改这些容器设置。如需调整宿主机端口或挂载位置，请编辑 Compose 文件。

### 公网部署

- 在 HTTPS 反向代理后部署，正确设置 `PUBLIC_URL` 和 `COOKIE_SECURE=true`。
- 仅当后端端口不直接暴露给不可信客户端时启用 `TRUST_PROXY=true`，避免伪造代理 IP 干扰限流。
- 反向代理请求体限制建议为 `110m`，上传超时至少 120 秒；保留续传 `PATCH` 请求。
- 如果通过 multipart 上传 MP4，代理请求体上限要高于配置的视频限额，默认可设为 `520m`。浏览器续传仍发送最多 4 MiB 的分片。
- 不要为 `/i/`、`/t/` 和随机图接口配置忽略响应头的 CDN 强制缓存。
- 不要把数据目录直接作为 Web 静态目录公开。

默认允许任意规范 HTTP(S) 来源跨域调用，跨域管理员 Cookie 不开放。需要限制来源时，在「设置中心 → 站点设置」开启跨域来源白名单；开启后只允许实际同源、`PUBLIC_URL` 和名单中的来源。该规则同时作用于普通 API 和断点续传，不替代接口授权，也不属于图片防盗链。

## 使用指南

### 管理与发布图片

1. **建立文件夹**：设置公开或私有权限。任意祖先文件夹为私有时，后代有效权限均为私有。
2. **上传图片**：支持静态 JPG、PNG、WebP，以及静态和动态 GIF。默认最大 100 MiB、4000 万像素，管理员可调低大小上限。GIF 最多 500 帧，像素按所有帧的画布合计。图片默认私有，公开需显式设置。
3. **配置随机服务**：选择全站、文件夹或自定义来源与媒体类型并启用，可填写“接口 slug”自定义调用地址。公开服务自动展示在首页，只选择公开资源。
4. **授权外部应用**：创建 API Key，按需分配操作权限与资源范围。
5. **管理删除**：图片先进入回收站；彻底删除由后台执行，存储失败时保留记录并重试。

**上传视频**：支持 H.264 视频和可选 AAC 音轨的 MP4，默认上限 500 MiB，可在「设置中心 → 图片处理」调整。视频原样保存并生成 WebP 封面，在后台和公开图库内播放。上传 API 使用 `mediaType=video`，S3 视频播放流量经过站点服务器。

上传暂停后可继续；刷新页面后，需要重新选择原文件恢复。浏览器只保存恢复元数据，不保存文件或长期 Key。缩略图异步生成，最长边为 640 px。

### 调用 API

公开随机服务启用后，可直接请求图片或 JSON：

```sh
# 返回随机图片字节
curl 'http://localhost:9521/api/v1/random?mode=image' -o random-image

# 返回图片信息和访问地址
curl 'http://localhost:9521/api/v1/random?mode=json'
```

在随机图服务中将“接口 slug”设为 `wallpaper` 后，可使用 `/api/v1/random/wallpaper` 调用，同样支持 `mode=image|redirect|json`。slug 可选，去除首尾空格并转为小写，最多 64 位，只允许字母、数字和中划线，首尾必须为字母或数字；不能与其他服务 slug 或服务 ID 重名。修改或清除后，旧 slug 地址失效，原有全站、文件夹和服务 ID 地址继续有效。slug 不替代私有服务授权。

随机图服务可配置为仅图片、仅视频或混合。要抽取 MP4，在仅视频或混合服务上请求 `?mode=json&mediaType=video`，再用返回的 `url` 播放。已有服务升级后默认仅图片。

使用具有目标文件夹 `upload` 权限的 API Key 上传图片：

```sh
curl -X POST 'http://localhost:9521/api/v1/upload?folderId=fld_ID&visibility=public' \
  -H 'Authorization: Bearer xh_YOUR_KEY' \
  -F 'file=@photo.png'
```

将 `fld_ID`、`xh_YOUR_KEY` 替换为实际值。以上多行命令使用 POSIX shell 语法；PowerShell 请使用 `curl.exe` 并将参数写在同一行。

上传权限不包含私有读取。私有读取需额外授予 `read`、`private:read` 和图片文件夹范围；私有随机调用还需 `random` 及相应服务范围。文件夹授权默认不包含子文件夹。

完整参数、鉴权、错误码和续传协议见 [API 文档](docs/api.md)。运行中的服务还提供 `/api/v1/openapi.json` 接口清单与 `/docs` 浏览器调用示例。

### 图片处理与 AI 归档

在设置中心启用处理策略，可调整格式、质量、最大宽高和原图保留。策略按「请求 → 文件夹 → 系统」逐字段取值；PNG 使用无损处理，透明图转 JPG 时填白，不放大图片。已有图片重新处理成功前，旧直链继续提供当前版本；失败的新图暂停公开，可重试或由管理员明确发布原图。

GIF 原样保存并跳过压缩、缩放和格式转换。浏览原图时保留动画，缩略图和 AI 预览使用首帧。

AI 归档需配置支持视觉输入的 Chat Completions 兼容接口，包括 Base URL、模型名、密钥和候选文件夹。仅向模型发送不超过 1024 px 的去元数据预览。未指定文件夹的新上传可自动分类，指定文件夹时默认保留归属；API 调用还需 `ai:classify` 权限，已有密钥不会自动获得该权限。

整理旧图时，进入「智能整理 → 手动任务」，选择来源文件夹、搜索并勾选图片后执行。支持跨页勾选，每批最多 100 张；重复、正在处理或分类、已删除的图片会跳过。可在工作区查看结果并人工归档。

### S3 存储与图片直链

S3 配置支持 Endpoint、Region、Bucket、凭证和 Path Style。使用时注意：

- **Bucket 保持私有**：后端鉴权后签发最长 5 分钟的 GET 临时地址，浏览器直接读取。Endpoint 必须可被访问者访问，HTTPS 站点需使用 HTTPS Endpoint。
- **长期保存逻辑地址**：`url`、`thumbnailUrl` 为临时地址，过期时间见 `urlExpiresAt`、`thumbnailUrlExpiresAt`（Unix 毫秒）；长期引用使用 `logicalUrl`、`logicalThumbnailUrl`。私有逻辑地址仍需授权或有效站内签名。
- **临时地址原样使用**：不要追加参数或替换域名。已签发的 S3 地址可能在站内权限修改或密钥撤销后继续可用，直至到期；删除对象、重新处理或迁移源副本清理也可能使其提前失效。
- **预留本地磁盘**：所有续传先暂存本地。`originals/`、`processed/`、`thumbnails/` 和 `migrations/` 前缀需由 XHImg 独占。

禁用存储不影响已有图片读取；存在图片、未完成上传等引用时，连接修改会受限。保存新的 S3 连接后页面会重新加载，以应用精确的图片来源 CSP。本地图片及随机图 `image` 模式仍由后端传输。

### 存储迁移

在「设置中心 → 存储迁移」按来源存储、文件夹筛选，或在资源列表勾选最多 100 张图片发起迁移。预览会冻结图片清单，需在 30 分钟内确认；默认不含子目录和回收站，可分别勾选。

迁移对当前图片、保留原图和缩略图去重复制，经目标回读及 SHA-256 校验后切换，保留图片 ID、站内直链、有效签名、内容、名称、权限和删除状态。复制失败时继续使用原位置。任务支持暂停、继续、取消和仅重试失败项；取消不回滚已完成项。

迁移不会修改系统或文件夹的新上传目标，迁空旧存储前需另行调整。成功后的源副本默认保留，管理员可在任务详情中确认清理；目标缺失或不可用时保留源副本。永久删除图片会同时删除迁移副本。源副本不替代一致性备份，云端复制与回读可能产生流量费用。

## 数据与维护

本地部署的默认数据布局：

```text
data/
├── xhimg.sqlite           # 数据库
├── objects/<storage-id>/  # 本地图片、派生文件及迁移对象
├── resumable/             # 未完成的续传数据
├── tmp/                   # 临时上传文件
├── chunks/                # 分片校验临时文件
├── work/                  # 图片处理和 AI 工作目录
└── migration-work/        # 迁移临时文件
```

升级前先停止写入，备份数据库、图片对象、`.env` 和对应版本。启动会自动执行尚未应用的 SQL 迁移；不要在已迁移的数据库上直接运行旧版本。S3 对象需单独备份。

Docker Compose 部署在备份并更新源码后，运行 `docker compose up -d --build xhimg` 重建镜像并启动；仅重启已有容器不会加载新代码或迁移文件。随机图 slug 随 `0007_random_slug.sql` 自动升级，已有服务默认不配置 slug，原地址保持有效，无需新增环境变量或修改数据卷。完整步骤见[升级说明](docs/operations.md#升级)。

**仅支持单实例运行，不要让多个实例共享同一数据目录。** `GET /health` 检查进程和数据库可访问性，S3 连通性需通过后台存储测试确认。

完整备份、恢复和故障处理见 [运维文档](docs/operations.md)。

## 本地开发

安装依赖并完成 `.env` 配置后，将 `PUBLIC_URL` 改为 `http://localhost:3801`：

```sh
pnpm dev
```

访问 `http://localhost:3801`。Vite 将 API、图片、缩略图和健康检查请求代理到后端 `9521` 端口。

技术栈：React 19、Vite、Tailwind CSS、Fastify、TypeScript、SQLite、Sharp 和 AWS SDK。项目使用 pnpm workspace：

```text
apps/web/        # 管理后台与公开页面
apps/server/     # API、鉴权、存储及后台任务
packages/shared/ # 共享定义
tests/           # Playwright 端到端测试
docs/            # API、运维、设计与验证记录
```

### 检查命令

```sh
pnpm typecheck
pnpm test
pnpm build

# 规模与资源检查
pnpm test:scale
pnpm test:resources
pnpm test:migration-scale
```

## 常见问题

### 上传完成后为什么看不到图片？

图片默认私有。需要公开时，同时检查图片自身和所有祖先文件夹的权限。启用处理或 AI 归档后，文件传输完成不代表已发布；请在上传中心查看后续任务是否完成或失败。

### 随机图接口为什么返回 404？

检查服务是否已启用，以及来源、标签、排除规则下是否存在可用候选。公开服务只选择已发布的公开图片，即使管理员调用也不会返回私有图片。

### 为什么保存的 S3 地址过一会儿就不能访问？

S3 预签名地址最长有效 5 分钟，应保存 `logicalUrl` 或 `logicalThumbnailUrl` 作为长期引用，访问私有图片时仍需授权。临时 URL 必须原样使用，不能追加参数或替换域名。

### 更新项目后需要重新生成主密钥吗？

不需要。请保留同一 `MASTER_KEY`，否则无法解密已保存的 S3 和 AI 凭证。升级前备份数据库、图片对象、配置与对应版本，详细步骤见[运维文档](docs/operations.md#升级)。
