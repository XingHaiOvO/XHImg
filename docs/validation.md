## 随机图 API 性能优化

日期：2026-11-02。环境：Windows、Node.js 24.16.0、pnpm 12.8.1。修改前后的测试均使用独立 SQLite 数据库与相同规模脚本，覆盖 1000 / 100000 张图片和三种响应模式。

实现取消候选 ID 排序与逐请求全量复制，改用最多三个位置的稀疏 Fisher-Yates 抽样；缓存失效、权限隔离和容量上限保持不变。image 模式复用一次 get 的流；json/redirect 仍每次 head，不缓存存在性结果。读取后重新校验调用者、当前服务规则、图片权限和存储位置；拒绝的流销毁并释放存储引用，旧位置缺失不能把已迁移图片误标为 missing。

`pnpm test:scale` 通过 Fastify inject 测量完整应用请求（不含外部 HTTP 连接），每组先记录一次冷请求，再预热 20 次、串行测量 200 次。模拟存储每次 head/get 使用 `setTimeout(1)`，image 返回 100 字节；Windows 调度使单次等待约 15ms，因此下表用于展示减少串行存储等待的效果，**不是实际 S3 延迟、生产吞吐或 50% 提速承诺**。每项均为单次运行观察值，冷请求还受 JIT 和文件缓存影响。

| 图片数 | 模式     | 冷请求 ms 前→后 | p50 ms 前→后 | p95 ms 前→后 | 串行请求/秒 前→后 |
| ------ | -------- | --------------- | ------------ | ------------ | ----------------- |
| 1000   | json     | 32.11→35.62     | 15.44→15.41  | 16.27→16.19  | 69.57→66.76       |
| 1000   | redirect | 16.12→15.08     | 15.49→15.46  | 16.57→16.24  | 65.65→65.38       |
| 1000   | image    | 31.04→17.21     | 30.90→15.38  | 31.98→16.14  | 34.85→67.70       |
| 100000 | json     | 72.18→52.46     | 15.45→15.42  | 16.14→16.27  | 65.94→68.97       |
| 100000 | redirect | 61.76→62.99     | 15.47→15.48  | 16.30→16.13  | 68.18→68.53       |
| 100000 | image    | 62.93→61.55     | 30.92→15.48  | 31.96→16.19  | 33.29→65.79       |

十万候选单独构建耗时 53.41→45.35ms；1000 次候选缓存命中合计 0.351→0.387ms。优化后的实际候选查询条件使用 image_candidates 索引，无 TEMP B-TREE；旧实现按 ID 排序存在临时排序树。冷构建仍随图库规模增长，缓存命中后的抽样只读取最多三个 ID。

每 200 个 image 请求的模拟存储调用由 200 HEAD + 200 GET 降为 0 HEAD + 200 GET；json/redirect 各保持 200 HEAD、0 GET。真实 AWS SDK 与本机 S3 协议夹具也断言 image 每次 0 HEAD + 1 GET，json/redirect 每次 1 HEAD + 0 GET，响应字节及临时直链行为正常。

验证命令：`pnpm test`、`pnpm typecheck`、`pnpm test:scale` 及修改文件的 Prettier 检查。服务端新增 22 个回归用例，覆盖抽样不复制/不变更共享候选、三次不同对象重选、暂时性错误、权限/服务/规则/位置变更、缺失迁移对象保护、密钥撤销/过期/读权限和授权范围变化、废弃流释放。浏览器测试未重跑。
