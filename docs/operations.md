# 运维与恢复

## 必须保留的内容

- SQLite 一致性备份，包含业务配置、用户密码摘要、密钥摘要及任务记录。
- 本地 `data/objects/` 原图和缩略图。
- `.env` 中的 MASTER_KEY、PUBLIC_URL 等配置。MASTER_KEY 丢失后无法解密 S3 凭证；勿将其与公开源码一起分发。
- S3 对象需要在供应商侧单独备份或启用版本控制，不包含在 SQLite 备份中。

## 本地备份

最简单的一致备份方式：停止应用后复制完整 `data/` 和 `.env`，再启动。不要在写入期间只复制主 `.sqlite` 文件而遗漏 WAL。

只备份数据库时，可使用 SQLite online backup API：

```sh
pnpm --filter @xhimg/server backup /absolute/backup/xhimg.sqlite
```

在线数据库快照不等于数据库与图片同时刻快照。完整恢复点应暂停写入，备份数据库及对应图片；未暂停时，至少保证备份期间不执行彻底删除，并保留对象版本以处理时间差。

## Docker 备份

```sh
docker compose stop xhimg
docker compose cp xhimg:/app/data ./xhimg-backup
# 单独安全复制 .env；同时保存对应源码/镜像版本。
docker compose start xhimg
```

恢复时先停止应用，将备份内容复制回持久卷，恢复同一 MASTER_KEY，确保数据归 UID/GID 1000 可读写；先用备份对应版本启动并检查，再升级。不要在新迁移后的数据库上直接运行旧版本代码。

## 失败恢复

- 原图写入前创建上传操作记录。对象已写入但数据库事务未提交时，操作标为 abandoned；异常退出后，下次启动会将未提交 writing 操作转为 abandoned 并回收对象。
- 已提交图片保留，缩略图失败不回滚原图；任务重试最多五次，使用递增延迟，失败任务可在概览中手动重试。
- 临时图片处理禁用 Sharp 操作缓存，避免 Windows WebP 内存映射锁住文件；清理错误不再把已生成的缩略图标记为失败，残留临时文件由清理任务回收。
- 彻底删除任务先标记 purging，实际删除两个对象后才删除数据库图片记录。失败保留对象位置并重试，删除任务不可恢复为正常图片。
- 对象删除失败每分钟重试；任务异常不暴露底层凭证。修复存储后等待任务重试或在概览重试失败任务。
- 原图缺失时图片标记 missing，不进入随机候选。恢复实际对象后，在图片编辑中“检查并恢复文件”。
- 过期会话与超过一天的临时文件由后台清理。后台任务单实例顺序运行；请勿共享同一 SQLite 目录启动多实例。

## 健康与日志

`GET /health` 检查进程及数据库可访问性，不代表所有 S3 供应商在线；存储连接需使用后台测试功能。日志记录请求 ID、方法与路径，不记录查询签名、Cookie、Authorization 或上传内容。初次安装令牌只在未安装启动时日志展示，应视为敏感信息。

容量统计为原图逻辑字节，不包含缩略图、数据库、临时文件或 S3 版本历史。为临时上传和备份预留磁盘空间。对外发布前配置 HTTPS、准确 PUBLIC_URL、Secure Cookie 与合适的反向代理信任边界。
