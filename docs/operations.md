# 运维与恢复

## 必须保留的内容

- SQLite 一致性备份，包含业务配置、用户密码摘要、密钥摘要及任务记录。
- 本地 `data/objects/` 原图、处理结果和缩略图；如需恢复续传，还需 `data/resumable/`。
- `.env` 中的 MASTER_KEY、PUBLIC_URL 等配置。MASTER_KEY 丢失后无法解密 S3 和 AI 凭证；勿将其与公开源码一起分发。
- S3 对象需要在供应商侧单独备份或启用版本控制，不包含在 SQLite 备份中。

## 本地备份

最简单的一致备份方式：停止应用后复制完整 `data/` 和 `.env`，再启动。不要在写入期间只复制主 `.sqlite` 文件而遗漏 WAL。

只备份数据库时，可使用 SQLite online backup API：

```sh
pnpm --filter @xhimg/server backup /absolute/backup/xhimg.sqlite
```

在线数据库快照不等于数据库与图片同时刻快照。完整恢复点应暂停写入，备份数据库及对应图片；未暂停时，至少保证备份期间不执行彻底删除，并保留对象版本以处理时间差。

## Docker 备份

```sh
docker compose stop xhimg
docker compose cp xhimg:/app/data ./xhimg-backup
# 单独安全复制 .env；同时保存对应源码/镜像版本。
docker compose start xhimg
```

恢复时先停止应用，将备份内容复制回持久卷，恢复同一 MASTER_KEY，确保数据归 UID/GID 1000 可读写；先用备份对应版本启动并检查，再升级。不要在新迁移后的数据库上直接运行旧版本代码。

## 失败恢复

- 原图写入前创建上传操作记录。对象已写入但数据库事务未提交时，操作标为 abandoned；异常退出后，下次启动会将未提交 writing 操作转为 abandoned 并回收对象。
- 已提交图片保留，缩略图失败不回滚原图；任务重试最多五次，使用递增延迟，失败任务可在概览中手动重试。
- 临时图片处理禁用 Sharp 操作缓存，避免 Windows WebP 内存映射锁住文件；清理错误不再把已生成的缩略图标记为失败，残留临时文件由清理任务回收。
- 彻底删除任务先标记 purging，实际删除原图、当前结果及缩略图的不同对象后才删除数据库记录。失败保留位置并重试，删除任务不可恢复为正常图片。
- 对象删除失败每分钟重试；任务异常不暴露底层凭证。修复存储后等待任务重试或在概览重试失败任务。
- 原图缺失时图片标记 missing，不进入随机候选。恢复实际对象后，在图片编辑中“检查并恢复文件”。
- 过期会话与超过一天的临时文件由后台清理。后台任务单实例顺序运行；请勿共享同一 SQLite 目录启动多实例。

## 健康与日志

`GET /health` 检查进程及数据库可访问性，不代表所有 S3 供应商在线；存储连接需使用后台测试功能。日志记录请求 ID、方法与路径，不记录查询签名、Cookie、Authorization 或上传内容。初次安装令牌只在未安装启动时日志展示，应视为敏感信息。

容量统计为当前结果与不同对象的保留原图，不包含缩略图、数据库、临时文件或供应商版本历史。为上传和处理预留磁盘空间。对外发布前配置 HTTPS、准确 PUBLIC_URL、Secure Cookie 与合适的反向代理信任边界。

## P0 升级到 P1

先停止写入并备份完整数据、环境配置及对应源码版本，再运行新版。备份命令以只读 SQLite 连接生成一致性快照，不触发迁移。不要先启动新版后才备份。新迁移 `0002_p1.sql` 为已有图片标记无需处理/分类、版本可用，不移动对象、不改变权限或图片 ID。升级后处理及 AI 默认关闭；现有 Key 不授予新权限。

处理任务保存策略快照。原图写入后，失败新图保持不可公开；后台可重试或选择使用原文件。已发布图片处理失败继续提供旧版本。新版先写独立对象并校验，再事务切换，旧对象进入持久化清理日志；不要手工清除待清理对象位置。

格式转换成功时，图片名称的扩展名与当前格式一起切换，失败保留旧名称。迁移 `0003_image_filenames.sql` 修正已完成转换的历史名称，不重新处理或移动文件；修正记录的访问版本会更新，旧签名需重新获取。源文件下载按保留源格式命名，缩略图下载使用 `.webp`。

续传字节放在 `resumable/`，已确认偏移保存在 SQLite。重启时截断超过确认偏移的尾部，不足则标记失败。分片验证临时文件在 `chunks/`，CPU/AI 工作目录在 `work/`，与旧 `tmp/` 清理规则分开。24小时未完成上传过期，默认最多20个、声明量2GiB；创建时预留未上传字节和512MiB工作空间。正在校验、处理和分类的任务由各自队列管理。

未发布图片移入回收站时暂停待执行处理/分类任务，恢复后继续。取消上传会使旧任务失效并保留回收站记录，恢复后可由管理员重新处理或归档；不因恢复而跳过发布隔离。

AI 独立单并发，默认60秒超时，网络/429/5xx额外重试最多两次；授权错误或无效结果直接失败。新图分类失败保持私有隔离，现有图片失败保留原归属。人工移动增加整理版本，旧结果不会覆盖移动。处理/缩略图共用单并发 CPU 队列，部署仍仅支持单实例。
