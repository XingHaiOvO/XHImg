# 部署与运维

[文档首页](README.md) · [安装与配置](../README.md#快速开始) · [API 参考](api.md) · [验证范围](validation.md)

本文说明数据保护、升级、运行检查和故障恢复。命令在项目根目录执行；使用自定义 `DATA_DIR` 时，将下文 `data/` 替换为实际目录。

## 部署约束

- 仅支持单实例，不要让多个进程或容器共享同一 SQLite 数据目录。
- 公网部署使用 HTTPS，设置准确的 `PUBLIC_URL` 和 `COOKIE_SECURE=true`。仅在后端端口不直接暴露给不可信客户端时开启 `TRUST_PROXY=true`。
- 反向代理请求体限制建议为 `110m`，上传超时至少 120 秒，保留续传 `PATCH` 请求。
- 数据目录不作为 Web 静态目录公开；图片访问必须经过应用的授权流程。
- 不要为图片、缩略图、随机图或 S3 跳转配置忽略响应头的强制缓存。

环境变量和 Docker 挂载方式见[配置说明](../README.md#配置说明)。Docker 实际构建、真实云服务和持续负载的历史验证限制见[验证记录](validation.md#未验证范围)。

## 数据与容量

### 需要备份的内容

| 内容                 | 作用与要求                                                   |
| -------------------- | ------------------------------------------------------------ |
| SQLite 一致性快照    | 保存业务配置、账号与密钥摘要、任务、对象位置及迁移源副本记录 |
| 本地 `data/objects/` | 包含原图、处理结果、缩略图及 `migrations/` 正式对象          |
| `data/resumable/`    | 需要恢复未完成续传时，与数据库一起保留                       |
| `.env`               | 保留同一 `MASTER_KEY` 和部署配置，单独安全保存               |
| S3 对象              | 由供应商侧单独备份或启用版本控制，不包含在 SQLite 快照中     |
| 源码或镜像版本       | 恢复时先运行与备份匹配的版本                                 |

`MASTER_KEY` 丢失后无法解密 S3 和 AI 凭证。不要把环境文件、备份或真实凭证随公开源码分发。

### 工作目录与统计

`tmp/` 保存临时上传，`chunks/` 保存待验证分片，`work/` 用于图片处理和 AI，`migration-work/` 用于迁移暂存。它们不替代正式对象备份。

图片容量统计包含当前结果与不同对象的保留原图，不包含缩略图、数据库、临时文件或供应商版本历史。迁移源副本单独计量，包含缩略图。实际占用可能高于页面显示的图片容量。

所有续传先暂存本地，即使最终存储是 S3 也需预留本地磁盘。默认允许 20 个未完成传输、2 GiB 声明量；创建时预留未上传字节及 512 MiB 工作空间，未完成上传默认 24 小时过期。

## 备份

### 停机完整备份

最直接的一致备份方式：停止应用，复制完整数据目录和 `.env`，备份对应 S3 对象，再启动。保存本次备份对应的源码或镜像版本。

不要在写入期间只复制主 `.sqlite` 文件而遗漏 WAL。数据库、图片对象及凭证必须能够共同恢复到匹配状态。

### 在线数据库快照

只备份数据库时可使用 SQLite online backup API：

```sh
pnpm --filter @xhimg/server backup /absolute/backup/xhimg.sqlite
```

替换目标路径为实际备份位置。该命令使用只读连接，不触发数据库迁移。

在线数据库快照不等于数据库与图片同时刻的完整快照。完整恢复点应暂停写入后备份数据库及对应对象；未暂停时，至少保证备份期间不执行彻底删除，并保留对象版本以处理时间差。

### Docker 数据备份

```sh
docker compose stop xhimg
docker compose cp xhimg:/app/data ./xhimg-backup
# 单独安全复制 .env，备份 S3 对象并保存对应源码或镜像版本。
docker compose start xhimg
```

每次使用独立的备份目标目录，避免与旧备份混合。命名卷是持久化位置，不是独立备份；不要使用会删除数据卷的清理操作代替升级。

## 恢复

1. 停止应用，保留当前数据，以便核对恢复结果。
2. 将匹配的数据库和对象恢复到数据目录；S3 对象按备份时的位置单独恢复。
3. 恢复同一 `MASTER_KEY` 及部署配置。
4. 确保运行用户对数据目录可读写。Docker 镜像使用 UID/GID `1000`。
5. 先使用备份对应版本启动，检查登录、图片读取、缩略图、存储连接和未完成任务，再考虑升级。

数据库中的迁移源副本和当前对象位置均需匹配实际对象。保留的源副本不包含完整站点状态，不能替代备份，也不提供一键回滚。

## 升级

### 通用流程

1. 停止写入并完成完整备份，记录当前版本。
2. 部署新源码或镜像并启动。
3. 启动会自动执行 `apps/server/migrations/` 中尚未应用的 SQL。
4. 检查 `/health`、登录、图片读取、存储连接及任务状态。

不要先启动新版再补做升级前备份，也不要在已执行新迁移的数据库上直接运行旧版本。需要回退时，恢复匹配的数据库、对象、配置和应用版本。

### 数据库迁移说明

P0、P1、P2 是历史开发阶段名称，不是对外发布版本号。

| 迁移                          | 作用与兼容性                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `0001.sql`                    | 初始数据库结构                                                                                 |
| `0002_p1.sql`                 | 增加处理、续传和 AI 状态；既有图片标记为无需处理或分类，不移动对象、不改变图片 ID 或权限       |
| `0003_image_filenames.sql`    | 修正已转换图片的历史文件名；不重新处理或移动对象，受影响记录更新访问版本，旧站内签名需重新获取 |
| `0004_storage_migrations.sql` | 增加存储迁移记录、存储版本和迁移锁                                                             |
| `0005_migration_counters.sql` | 增加迁移计数触发器                                                                             |
| `0006_migration_indexes.sql`  | 增加队列、分页及对象引用索引                                                                   |

处理与 AI 默认关闭，已有 Key 不会自动获得 `ai:classify`。增加迁移表不会自动复制图片；只有管理员创建预览并确认后才执行存储迁移。

来源白名单开关缺失的旧配置按关闭处理，原名单保留，需管理员手动启用。S3 短期直链和来源白名单调整无需新增数据库迁移，不自动更改桶权限或现有对象位置。

## 图片与任务恢复

| 情况                   | 系统行为                                                         | 处理方式                                           |
| ---------------------- | ---------------------------------------------------------------- | -------------------------------------------------- |
| 写入对象后未提交数据库 | 上传操作记为 `abandoned`，异常退出后启动恢复未提交操作并回收对象 | 检查存储与日志，避免手动删除操作记录               |
| 缩略图失败             | 保留已提交图片，最多五次任务重试，使用递增延迟                   | 在概览重试失败任务                                 |
| 新图处理或分类失败     | 暂停对非管理员发布                                               | 在上传中心重试，或由管理员明确使用原文件结束任务   |
| 已发布图片重新处理失败 | 继续提供旧版本                                                   | 修复原因后重新处理                                 |
| 原图缺失               | 标记 `missing`，排除随机候选                                     | 恢复实际对象后，在图片编辑中执行「检查并恢复文件」 |
| 彻底删除失败           | 保留 `purging` 状态及对象位置，不提前删除记录                    | 修复存储后等待或重试；对象删除失败每分钟重试       |
| 续传重启               | 按数据库确认偏移恢复，截断多余尾部；文件不足则失败               | 刷新后重新选择原文件恢复，或重新上传               |

重新处理先写独立对象并校验，事务成功后切换版本，旧对象进入持久化清理记录。不要手动移除待清理对象的位置记录。格式转换成功时，文件名扩展名随当前格式切换；保留源文件按源格式下载，缩略图使用 `.webp`。

未发布图片移入回收站时暂停待执行处理和分类，恢复后继续。取消上传使旧任务失效并保留回收站记录；恢复后可由管理员重新处理或归档，不会绕过发布隔离。彻底删除任务不能恢复为正常图片。

AI 使用独立单并发队列，默认 60 秒超时，网络、429、5xx 额外重试最多两次；授权错误或无效结果直接失败。既有图片分类失败保留原归属，人工移动使旧整理结果失效。图片处理与缩略图共用单并发 CPU 队列。

临时图片处理禁用 Sharp 操作缓存，避免 Windows WebP 文件锁。临时文件清理失败会独立重试，不把已生成的缩略图改为失败。过期会话与超过一天的临时文件由后台清理。

### 存储迁移恢复

- 暂停或取消先中断 I/O，再确认状态；取消不撤回已完成项。
- 重启根据数据库恢复队列与控制状态、清除旧锁；已存在目标对象重新校验后复用，成功项不重复提交。
- 单个瞬态失败最多额外重试两次；内容校验不符直接失败，磁盘不足暂停整批。修复后继续或仅重试失败项；内容或存储版本已变化时重新预览。
- 终态任务的源副本需明确确认清理。清理前验证当前目标，目标缺失或损坏时保留源副本，活跃读取或图片变更时延后清理。
- 存储连接被源副本、活跃任务或残留目标引用时不能更换或删除。彻底删除图片会同时回收当前与历史迁移对象，失败时保留位置。
- 迁移不调整系统或文件夹默认上传目标。迁空旧存储前先调整新上传规则；来源可停用，目标必须启用。

`migration-work/` 仅清理服务生成的非运行明细目录，不触碰正式对象。首次使用迁移时先用少量隔离图片检查目标权限与费用。完整操作见 [API 存储迁移](api.md#存储迁移)。

### 空目录回收

本地对象删除或写入失败后会逐级回收空父目录，保留存储根目录。启动时，在接受请求和启动后台队列前扫描 `data/objects/`，回收历史空子目录，包括已删除存储配置遗留的目录。

回收只使用非递归目录删除，不删除文件，不跟随符号链接或目录联接；非空、占用或无法访问的目录保留。工作目录不在该扫描范围内，也不会因此删除迁移源副本。

## 来源限制与 S3 访问

### 浏览器来源白名单

在「设置中心 → 站点设置」手动启用。空名单启用后仅允许实际同源与 `PUBLIC_URL`；开关和名单保存后立即作用于 API 与续传，无需重启。

该配置不开放跨域管理员 Cookie，不替代 CSRF 或 API Key 校验，不自动修改 S3 桶 CORS，也不是防盗链或 IP 访问控制。

### S3 直链与缓存

Bucket 保持私有。Endpoint 必须可被图片访问者访问，不能仅在容器网络中解析；HTTPS 站点需使用 HTTPS Endpoint。应用按 SDK 解析结果生成精确图片 CSP，保存新连接后管理页会重新加载；已有浏览器页面也应刷新。

客户端使用后端授权签发的最长 5 分钟 GET 地址。URL 必须原样使用，不追加参数、不替换域名；长期引用保存站内逻辑地址。预签名地址及包含签名的 `Location` 均是临时凭证，不应写入公开日志、分析平台或持久化配置。

S3 响应通过签名参数覆盖为 `private, no-store`，不要强制缓存响应或跳转。站内权限修改、Key 撤销或会话失效会阻止后续签发与逻辑地址访问，但不保证已签发 S3 地址立即失效。对象删除、重新处理或源副本清理也可能使旧地址提前失效。

供应商侧访问日志、CDN 日志与桶 CORS 由部署者管理。供应商兼容性仍需在目标环境联调，见 [S3 验证限制](s3-links-validation.md#限制)。

## 健康检查与日志

`GET /health` 检查进程和数据库可访问性，不代表所有存储供应商在线。S3 连接使用后台测试功能单独确认。

日志记录请求 ID、方法与路径，不记录查询签名、Cookie、Authorization 或上传内容。初次安装令牌仅在未安装时的启动日志展示，应作为敏感信息保存。
