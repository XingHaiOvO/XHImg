## 自动化检查

- 完整后端 51 个用例、5 条浏览器流程通过；前后端类型检查、生产构建及格式检查通过。迁移页面按需加载，主 JS 约 492KB（gzip153KB），迁移页面独立约 11.6KB。

## 功能与一致性覆盖

- 迁移核心用例覆盖：本地与 S3 往返、不同本地配置、共享 Bucket 的两套 S3 配置；原图、当前结果和缩略图一起切换，旧签名可继续读取实际字节，权限和版本保持。
- 一致性用例覆盖：同大小错误内容、事务切换失败、磁盘不足暂停、源副本活跃读取、目标缺失禁止清理、彻底删除全部迁移副本、重复预览和任务占用、草稿过期、回收站及子文件夹范围。
- 额外验证截断来源不会切换、复制和源删除故障可重试、历史引用最终释放、临时目录回收不删除非服务目录；迁移 I/O 等待期间仍可执行其他图片上传和缩略图任务。
- SQLite 一致性备份与对象目录复制恢复到独立数据目录后，当前结果、保留原图和迁移源副本均可读取；恢复不会自动删除源副本，明确 cleanup 后才清理。
- 真实 SDK 中断用例在 PUT 已接收但未响应时暂停，验证请求中断、迁移锁释放；模拟重启恢复后复核已有目标字节，未重复上传或累计成功数。SDK 可能输出预期的流式请求中断提示，任务结果验证通过。
- AI 视觉接口使用本机夹具，在模型等待期间完成物理迁移，再提交逻辑归档；文件夹、私有权限及目标存储均正确。
- 浏览器验证设置中心添加迁移目标、资源列表勾选、冻结预览、确认执行、旧直链读取、明确确认源副本清理、空筛选不可执行，以及 390px 手机布局。截图在 `test-results/storage-migration-*.png`。

## 规模与资源观察

`pnpm test:migration-scale`：100000 张元数据记录。冻结预览约 1883ms，确认入队约 1601ms，1000 次队列头查询约 10.6ms，RSS 约 296MiB。队列计划使用 migration_items_task(task_id,state)索引，无临时排序；无状态明细分页使用 migration_items_pages。报告为 `.cache/p2-scale.json`。

`pnpm test:resources`：100MiB 源 PNG 经过 P1 处理后，迁移其原图、当前 JPG 和缩略图三个对象。本地到本地，包含预览、流式暂存、SHA-256 回读校验和切换，耗时约 0.44 秒，CPU 时间约 0.72 秒，采样峰值 RSS 约 346MiB（迁移开始基线约 313MiB）。源副本仍保留。报告为 `.cache/p2-resources.json`。这是开发机观察，不是生产性能承诺。

## 限制

Docker 实际构建运行、真实云服务商、真实模型、2 核 2GB VPS 持续并发尚未验证。本机 S3 夹具使用真实 AWS SDK 签名与 HTTP 传输，但不代表已验证 AWS、R2、MinIO 等具体供应商。磁盘不足用受控故障验证暂停流程，未实际耗尽开发机磁盘。

原验证记录确认未对正式图片执行迁移或清理；本机备份快照与报告位于忽略目录，不随仓库分发。共同限制见[验证索引](validation.md#未验证范围)。
